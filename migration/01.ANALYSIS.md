# AgentScope Web UI 前端项目分析报告（Vue 2 迁移参考）

> 分析日期：2026-09-05
> 目标：为将该 React 项目迁移到 **Vue 2 + Composition API** 提供完整的结构参考与实施路径。
>
> **核心结论（先读这一段）**：
> - 业务分层的可复用性很高：`src/api/`（纯 TS，框架无关）、`src/utils/`、`src/i18n/locales/*.json`、`src/index.css` 主题变量、`src/api/types.ts` 类型定义 **几乎可以原样复用**。
> - 工作量集中在三处：① shadcn/ui + radix-ui 组件体系（约 40 个 UI 组件）需替换为 Vue 2 生态组件库或自实现；② React 专用库（streamdown / onborda / framer-motion / react-resizable-panels / react-diff-view）需找 Vue 2 等价物；③ 聊天流式渲染链路（SSE → useMessages → ASMessageBubble → tool-renderers）是最复杂的单点，需要按 Vue 2.7 响应式模型重写。
> - 建议使用 **Vue 2.7.16**（Vue 2 最终版本，内置 Composition API + 官方 `@vitejs/plugin-vue2`），而不是 Vue 2.6 + `@vue/composition-api` 插件。

---

## 1. 项目概述

本项目是 [docs.agentscope.io](https://docs.agentscope.io/) 配套的 AgentScope 平台 Web UI 示例，与后端（FastAPI，默认 `http://localhost:3000`，前端通过 Vite 代理 `/api` 转发）通信，功能涵盖：

- 多 Agent 聊天（SSE 流式回复、工具调用可视化、HITL 人工确认、多智能体 team 视图、流式语音回复）
- 管理域：Agent 配置、MCP 管理 + MCP Hub、Skill 管理 + Skill Hub、知识库（文档上传/检索测试）、渠道（Channel）、凭据（Credential）、定时任务（Schedule，cron + 日历视图）、初始设置向导

**当前技术栈**：React 19 + TypeScript 6 + Vite 8 + Tailwind CSS v4 + shadcn/ui（radix-ui）+ react-router-dom v7 + react-i18next。无 Redux/Zustand，状态全靠 hooks + Context。

**规模**：约 200 个 TS/TSX 源文件。

## 3. 路由结构（react-router-dom v7 → vue-router 3）

```ts
// App.tsx 中的完整路由表
{
  element: <AppLayout />,            // 外层布局（侧边栏 + Outlet），errorElement: RouteError
  children: [{
    errorElement: <RouteError />,    // 内容级错误边界：页面崩溃不影响侧边栏
    children: [
      { path: '/',                                        redirect→ /chat },
      { path: '/chat/:agentId?/:sessionId?/:memberId?',   element: ChatPage },   // 可选参数
      { path: '/schedule',   element: SchedulePage },
      { path: '/channel',    element: ChannelPage },
      { path: '/credential', element: CredentialPage },
      { path: '/mcp',        element: MCPHubPage },
      { path: '/mcp/:hubId', element: MCPHubPage },        // hub 详情（same component）
      { path: '/skill',      element: SkillHubPage },
      { path: '/skill/:hubId', element: SkillHubPage },
      { path: '/knowledge',  element: KnowledgePage },
      { path: '/knowledge/:kbId', element: KnowledgePage },
    ],
  }],
},
{ path: '/setup', element: SetupPageRoute, errorElement: <RouteError /> }  // 独立于布局
```

**启动门禁**：`App` 组件检查 `localStorage.getItem('server_url')`，未完成 setup 时直接渲染 `SetupPage`（不走路由）。

**URL 即状态**：聊天页的 agentId/sessionId/memberId 全部在 URL 上，由 `ChatPage` 解析参数、处理默认值并用 `navigate` 重写 URL（Vue 中对应 `useRoute().params` + `router.replace`）。

## 4. Provider / 全局状态层级

```
main.tsx:  TooltipProvider(shadcn) → App
App.tsx:   OnbordaProvider → Onborda(新手引导, steps=chatTour) 
             → UploadProvider(上传队列)
               → RouterProvider
             + Toaster(sonner, top-right)     ← 注意在 Router 之外，全局唯一
```

迁移时对应关系：

| React 实现 | 职责 | Vue 2.7 建议实现 |
|---|---|---|
| `UploadContext`（useReducer：ADD/START/PROGRESS/UPLOAD_DONE/UPLOAD_FAILED/CANCEL/REMOVE/SERVER_STATUS/CLEAR_FINISHED） | 知识库文档上传任务队列，含并发限制 `MAX_CONCURRENT_UPLOADS`、按 KB 查询/合并服务端状态 | `provide/inject` 一个 `useUploadCenter()` composable（内部 `reactive([])` + 纯函数 reducer） |
| `AudioContext` + `StreamingAudioManager`（utils/streamingAudio.ts） | 按 blockId 订阅音频块播放状态 | 同上，`useAudioBlock(blockId)` 用 `provide/inject` |
| `TooltipProvider`、`sonner Toaster`、`OnbordaProvider` | UI 基础设施 | 组件库自带 / vue-toastification / driver.js |

**没有全局 store**。所有业务状态都是页面级 hooks（局部 useState/useEffect）。迁移时保持同样的粒度即可，不需要引入 Vuex；如团队偏好，可引入 Pinia（支持 Vue 2.7）管理 SSE 消息流这类跨组件状态。

## 5. 数据层（src/api/，可直接复用）

### 5.1 client.ts 要点

- 基于**原生 fetch**（非 axios），统一注入 `X-User-ID` 头（localStorage）、解析 FastAPI/Pydantic 422 错误（配合 `lib/api-error.ts` 转成可读 msg）、支持 `silent` 模式（静默失败不弹错）、超时控制。
- 暴露 `get/post/patch/delete` + **`stream(path, options)`**：只返回 `Response`，SSE 解析交给上层。

### 5.2 SSE 流式协议（聊天核心，必须原样保留）

```
触发:  POST /chat/            → fire-and-forget，响应中不含事件
推送:  GET  /sessions/{sid}/stream → SSE 长连接（sessionApi.streamEvents()）
```

- **不用 EventSource**（因为要带 `X-User-ID` 自定义头），而是 `fetch` + `response.body.getReader()` 手工解析：按行拆分缓冲，`data:` 前缀后为 JSON（`AgentEvent`），`:...` 注释帧是心跳，跳过。
- `streamEvents` 是 **async generator**，调用方（useMessages）用 `AbortSignal` 或关闭 generator 终止连接。
- 事件类型包括（来自 useMessages 的事件处理）：`REPLY_START` / `REPLY_END` / `DATA_BLOCK_DELTA` / `DATA_BLOCK_END`（文本/音频等流式块）、工具调用相关事件、HITL 待确认请求、团队（subagent）通知等，全部定义在 `api/types.ts` 的 `AgentEvent`。

## 6. 核心复杂度：聊天链路

### 6.1 消息渲染管线

```
SSE AgentEvent ──useMessages(processEvent)──> Msg[]（api/types.ts 结构）
     │
ChatViewport ──> ChatContent ──> 每条 Msg
     │
ASMessageBubble:
  - 将 @agentscope-ai/agentscope/message 的 ContentBlock
    （TextBlock / ToolCallBlock / ToolResultBlock / ThinkingBlock / DataBlock(音频)…）
    经 groupToolCalls 聚合成 tool_call_group
  - 按 finished_at 判定运行中/完成，底部展示 duration / token 统计
  - 文本块 → Markdown(streamdown) 渲染；音频块 → AudioContext 播放
```

### 6.2 tool-renderers 注册分发体系

- `types.ts`：Renderer 接口 = 可选实现 `getDisplayName` / `renderConfirmBody` / `renderHeader` / `renderBody`。
- `index.tsx`：`renderers` 注册表按 tool name 分发（`Bash/Read/Write/Edit/Glob/Grep/TaskCreate/Default`），`renderToolCall` 统一渲染。
- `_shared.tsx`：`ToolCallRow` 提供 collapsible 外壳（折叠状态、状态图标、chevron、运行中 shimmer），各 renderer 只提供 header/body 片段。
- `DiffPreview.tsx`：用 `unidiff` 解析 + `react-diff-view` 展示 Edit/Write 的 diff。
- **Vue 迁移建议**：保留“注册表 + 接口”设计，改为「组件映射表」：`{ bash: BashRenderer, read: ReadRenderer, ... }`，接口改为定义 props + 具名插槽（header/body/confirmBody）。

### 6.3 HITL（人工确认）

- `ConfirmCard.tsx`：单条 `ToolCallBlock` 的确认卡片（允许/拒绝 → `POST /chat/` 携带确认事件）。
- `SubagentHitlCard.tsx`：team 模式下把成员 session 的 pending 确认汇总到 leader 视图。
- 确认 body 由对应 tool renderer 的 `renderConfirmBody` 提供。

### 6.4 流式音频（utils/streamingAudio.ts，★ 框架无关可直接复用）

- Omni 模型语音经 `DATA_BLOCK_DELTA`（base64 音频字节）流式到达，两种播放路径：
  1. **WAV**：解析 RIFF 头，后续 PCM 字节实时排入 Web Audio timeline（首包即播，不等 DATA_BLOCK_END）；`finalize` 延迟销毁 AudioContext 防止截尾。
  2. **非 WAV（mp3/opus）**：累积字节，DATA_BLOCK_END 时生成 Blob URL 供 `<audio>` 播放/拖动。
- 该文件是纯 TS + Web Audio API，**无 React 依赖，直接复制**；`AudioContext.tsx` 只是其上的状态订阅壳，需用 Vue 重写。

## 8. UI 组件体系（迁移工作量评估）

### 8.1 shadcn/ui 基础组件（40 个，radix-ui 原语 + cva + tailwind）

`alert attachment avatar badge bubble button button-group calendar card checkbox collapsible dialog drawer dropdown-menu empty field input input-group item kbd label marker message message-scroller popover progress resizable select separator sheet sidebar skeleton sonner spinner switch table tabs textarea toggle tooltip`

迁移策略二选一：
1. **引入 Vue 2 组件库**（Element UI / Ant Design Vue 1.x / Vuetify 2）替换大部分，仅手写 message/bubble/attachment/message-scroller/sidebar 等业务化组件 —— 改动小、风格会变；
2. **保留 Tailwind v4 + 逐个手写 Vue 版 shadcn 组件** —— 视觉 100% 还原（tailwind class 可原样搬），工作量大但可控，样式零改动。

> 推荐：**方案 2**（Tailwind 与框架无关，`cn()`/cva 思路在 Vue 2 中照用），优先实现页面用到的子集，不必 40 个全做。

### 8.2 关键第三方依赖映射（React → Vue 2）

| 依赖 | 用途 | Vue 2 替代方案 |
|---|---|---|
| react / react-dom / @vitejs/plugin-react | 框架 | vue@2.7.16 + @vitejs/plugin-vue2 |
| react-router-dom v7 | 路由 | vue-router@3（2.7 兼容线） |
| react-i18next + i18next | i18n（en/zh JSON，浏览器语言检测） | **vue-i18n@8**，locale JSON 直接复用 |
| @agentscope-ai/agentscope | 消息数据结构（ContentBlock 等）+ 部分 React 组件 | **类型直接复用**；ASMessageBubble 等组件需 Vue 重写 |
| streamdown + @streamdown/{code,math,cjk,mermaid} | 流式 Markdown（代码高亮/KaTeX/mermaid/CJK） | React 专用，替代：markdown-it + highlight.js + markdown-it-katex + mermaid；流式增量渲染需自封装（见风险 R2） |
| shadcn-prose / @tailwindcss/typography | Markdown 排版 | 保留 Tailwind 插件即可 |
| framer-motion | 动画（tour 卡片 spring 等） | Vue `<transition>`/`<transition-group>` + CSS；复杂动效用 GSAP |
| onborda（依赖 next-themes、framer-motion） | 新手引导（selector/side/pointer 步骤，TourCard 自定义卡片，完成标记 `chat_tour_done`） | **driver.js**（框架无关，步骤语义最接近） |

| react-diff-view + unidiff | 工具 diff 预览 | unidiff 是纯 JS 可复用；视图用 v-code-diff（vue2 分支）/ vue-code-diff 或自渲染 |
| react-day-picker | schedule 日历 | vue2-datepicker / Element UI DatePicker，或手写月历 |
| cron-parser / date-fns | cron 展开与日期格式化 | **纯 JS，直接复用** |
| radix-ui | 无障碍原语 | 无（组件库内部已实现） |
| class-variance-authority / clsx / tailwind-merge | 样式工具 cn() | **纯 JS，直接复用** |
| lucide-react / lucide | 图标 | lucide 无 Vue2 官方包；用 Iconify（lucide 图标集）或导出 SVG + vite-plugin-svgr→vite-svg-loader |

## 9. 构建配置迁移要点

- `vite.config.ts`：`@vitejs/plugin-react` → `@vitejs/plugin-vue2`；`vite-plugin-svgr` → `vite-svg-loader`；`@tailwindcss/vite`、`/api` 代理、`@` 别名、`optimizeDeps.include: ['mime-types']` 原样保留。
- TS：vue2.7 支持组合式 API 的完整类型推导（`defineComponent({ setup() {...} })`），`tsconfig` 基本可沿用；增加 `env.d.ts` 声明 `.vue` 模块。
- ESLint：`eslint-plugin-react-hooks` → `eslint-plugin-vue`（vue2 essential 规则集）。

## 12. 主要风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | **Vue 2 响应式基于 defineProperty**：SSE 高频 delta 更新 + 长消息数组，更新粒度不当会造成卡顿 | 消息流增量更新时优先整块替换单条 Msg（`msgs.value[i] = {...}`），避免深层字段细粒度修改；超长消息文本合并节流（如 50ms flush）；虚拟滚动长会话 |
| R2 | **streamdown 无 Vue 版**：流式 Markdown 增量渲染 + 代码高亮是体验关键 | markdown-it 渲染 + `v-html` 需注意 XSS（保留 DOMPurify）；增量渲染做 throttle；mermaid 单独异步渲染 |
| R3 | React 专用库需逐个替代（§8.2），个别（vaul/onborda）没有等价物 | driver.js / splitpanes / vue-toastification 已验证可行；drawer 数量少可自实现 |
| R4 | Vue 2.7 已停止维护（EOL），安全补丁不再更新 | 团队已明确 Vue 2 前提，记录该风险；升级路径上保持 composables 写法与 Vue 3 兼容（不使用 `this`、选项式 API），便于将来平移 |
| R5 | `@agentscope-ai/agentscope` 若后续发版新增 UI 组件，Vue 侧无法跟进 | 只依赖其**类型定义**（ContentBlock/Msg/AgentEvent），UI 全部自持 |
| R6 | 聊天链路回归成本高 | Phase 0 就录制 SSE fixture，用回放做自动化冒烟；与旧版双开对照 |
