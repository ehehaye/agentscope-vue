## 1. 技术选型锁定

### 1.1 核心依赖

| 角色 | 选型 | 版本 | 说明 |
|---|---|---|---|
| 框架 | `vue` | **2.6.14** | 团队既定基线。2.6 不内置 Composition API，需配插件。 |
| Composition API | `@vue/composition-api` | ^1.7.2 | Vue 2.6 启用组合式 API 的官方插件，必须在 `main.js` 中 `Vue.use()` 注册后再使用 `ref/reactive/...`。 |
| 状态管理 | `vuex` | **3.6.2** | Vuex 3 是 Vue 2 兼容线；使用 **modules** 切分功能域，不污染全局 state。 |
| 路由 | `vue-router` | **3.6.5** | Vue 2 兼容线，对应 React 的 react-router-dom v7。 |
| 构建工具 | `vite` + `vite-plugin-vue2` | vite ^4 / vite-plugin-vue2 ^1.8 | `vite-plugin-vue2`（underfin）面向 Vue 2.6；**不要用** `@vitejs/plugin-vue2`（那是 Vue 2.7 专用）。 |
| 样式 | `tailwindcss` v4 + `@tailwindcss/vite` | 同旧版 | Tailwind 与框架无关，`cn()`/cva 思路原样保留。 |
| SVG | `vite-svg-loader` | ^4 | 替代 `vite-plugin-svgr`，`import Logo from '@/assets/logo.svg'` 同样可用。 |
| Toast | `vue-toastification` | ^1.7.14 | v1 线支持 Vue 2，替代 sonner。 |
| 新手引导 | `driver.js` | ^1.x | 框架无关，替代 onborda。 |
| 分栏 | `splitpanes` | ^2.x | 支持 Vue 2，替代 react-resizable-panels。 |
| Markdown | `markdown-it` + 插件链 | — | 替代 streamdown，详见 §10。 |
| Diff 预览 | `v-code-diff` 或自渲染 + `unidiff` | — | `unidiff` 纯 JS 直接复用。 |
| 日期 | `vue2-datepicker` 或 Element DatePicker | — | 替代 react-day-picker；`date-fns`/`cron-parser` 纯 JS 直接复用。 |
| 图标 | Iconify（lucide 图标集） | — | lucide 无 Vue2 官方包，用 Iconify 统一加载。 |

### 1.2 明确「不引入」的项

| 项 | 决定 | 原因 |
|---|---|---|
| TypeScript | **不引入，纯 JS** | 团队既定。`api/`、`utils/` 去 TS 化（剥类型注解），用 JSDoc 保留关键契约。 |
| i18n | **不引入，默认中文** | 团队既定。移除 vue-i18n 与 locales，所有 `t('xxx')` 调用点替换为直接中文字符串。 |
| Pinia | **不引入** | 团队选定 Vuex；与 Vue 2.6 兼容性更好，modules 模式成熟。 |
| Vue 2.7 | **不升级** | 团队锁定 2.6.14。接受 EOL 风险（见 §13 R4），写法保持与 Vue 3 平移兼容。 |
| `<script setup>` | **不可用** | Vue 2.6 + composition-api 插件不支持；统一用 `defineComponent({ setup() {} })` 或 `export default { setup() {} }`。 |

01 文档建议「Vue 2.7.16 + 可选 Pinia + 保留 i18n/TS」，本方案按团队要求调整如下：

## 3. 状态管理总体策略

### 3.1 三层分层规则

本项目 React 侧「无全局 store，全靠 hooks + Context」。迁移遵循团队原则「**优先 hooks，有必要才用 Vuex，Vuex 与 provide/inject 不冲突**」，按下表分层：

| 层 | 载体 | 适用场景 | 生命周期 |
|---|---|---|---|
| **L1 局部状态** | composable 内 `ref/reactive` | 单组件或单页面内部状态：列表 CRUD、表单、轮询、schema 拉取 | 组件卸载即销毁 |
| **L2 跨组件共享（有界）** | `provide/inject` + composable | 状态在某个子树内多组件共享，且不希望污染全局：音频管理、资源抽屉 | provide 方卸载即销毁 |
| **L3 全局 / 跨页共享** | **Vuex modules** | 真正全局或跨页面、跨层级共享：app 配置、聊天 SSE 流、工作区状态、上传队列 | 应用级常驻 |

判定优先级：**L1 → L2 → L3**。能 L1 不 L2，能 L2 不 L3。只有当「多个无父子关系的组件 / 多个页面」需要读写同一份状态时，才升 L3。

### 3.2 各状态归属裁定

| React 来源 | 性质 | 迁移归属 | 理由 |
|---|---|---|---|
| 各 `useXxx` CRUD hook（sessions/agents/channels/credentials/schedules/mcps/skills/knowledgeBases/...） | 页面内列表+CRUD | **L1 composable** | 仅页面内用，切页即销毁；React 侧也是页面级 useState。 |
| `useModels/useAvailableModels/useAvailableTTSModels/useKbEmbeddingModels/useChunkers` | 选项列表 | L1 composable | 同上，按需在用到的页面/对话框内独立请求即可（可加本地缓存）。 |
| `useAgentSchema/useKnowledgeBaseMiddlewareSchema/useKnowledgeSupportedContentTypes` | schema 驱动表单 | L1 composable | 跟随所属对话框生命周期。 |
| `useDocumentStatusPolling` | 文档状态轮询 | L1 composable | 绑定 knowledge 详情组件。 |
| `useResourceDrawer` | 抽屉开合 | L2 provide/inject | 页面内多组件触发同一抽屉。 |
| `AudioContext` + `StreamingAudioManager` | 流式音频管理 | **L2 provide/inject**（`useAudioCenter`） | 仅聊天子树用；manager 是有状态对象，provide 一个实例最自然，无需全局。 |
| `UploadContext`（上传队列 + 调度器） | 跨页常驻 + 调度器 | **L3 Vuex `upload` 模块** | React 侧挂 App 级；含并发调度器与 beforeunload 警告，需跨页存活；放 Vuex 便于 devtools 观察。 |
| `useMessages`（SSE 消息流） | 跨组件共享 | **L3 Vuex `chat` 模块 + `useMessages` composable 封装** | 团队明确点名「SSE 消息流这类跨组件状态」用 Vuex；ChatViewport/TextInput/各 Panel 都要读。 |
| `useWorkspace/useWorkspaceStatus` | 侧边栏 + 多页共享 | **L3 Vuex `workspace` 模块** | 侧边栏展示工作区状态，多个页面读目录。 |
| server_url / user_id / dark / setupCompleted | 全局 | **L3 Vuex `app` 模块** | 启动门禁、请求头注入、主题切换都要用。 |

> 说明：`useMessages` 仍以 composable 形态存在，但它内部不再持有状态，而是 `import { useStore } from 'vuex'` 读写 `chat` 模块，并对外暴露与原 hook 同名的 actions（`send/onUserConfirm/onSubagentConfirm/interrupt`）。这样调用方写法不变，状态真正落 Vuex。

## 4. Vuex 模块设计

全部模块开 `namespaced: true`，避免全局 mutation/action 命名冲突。每个模块只管自己的功能域，互不污染。

### 4.1 `app` 模块

```js
// store/modules/app.js
export default {
  namespaced: true,
  state: () => ({
    serverUrl: localStorage.getItem('server_url') || '',
    userId: localStorage.getItem('x-user-id') || '',
    dark: localStorage.getItem('theme') === 'dark',
    setupCompleted: !!localStorage.getItem('server_url'),
  }),
  mutations: {
    SET_SERVER(state, url) { state.serverUrl = url; },
    SET_USER(state, id) { state.userId = id; },
    SET_DARK(state, v) { state.dark = v; },
    SET_SETUP_DONE(state, v) { state.setupCompleted = v; },
  },
  actions: {
    completeSetup({ commit }, { url, userId }) {
      localStorage.setItem('server_url', url);
      if (userId) localStorage.setItem('x-user-id', userId);
      commit('SET_SERVER', url);
      commit('SET_USER', userId || '');
      commit('SET_SETUP_DONE', true);
    },
    toggleDark({ commit, state }) {
      const v = !state.dark;
      localStorage.setItem('theme', v ? 'dark' : 'light');
      document.documentElement.classList.toggle('dark', v);
      commit('SET_DARK', v);
    },
  },
};
```

要点：`serverUrl` 决定 `api/client.js` 的 baseURL（迁移后由 `client.js` 直接读 localStorage，或通过 `store` 注入——为保持 api 层框架无关，**仍走 localStorage**，Vuex 仅作 UI 镜像）。

### 4.2 `chat` 模块（核心）

承载活跃 `(agentId, sessionId)` 的消息流与 SSE 状态机。这是整个迁移的最高风险点，单独成模块便于隔离调试。

```js
// store/modules/chat.js  （骨架，完整事件分发见 §10）
export default {
  namespaced: true,
  state: () => ({
    agentId: null,
    sessionId: null,
    memberId: null,
    messages: [],          // Msg[]（结构对照 api/types 的 Msg）
    loading: false,        // 历史拉取中
    phase: 'idle',         // 'idle' | 'streaming' | 'interrupting'
    error: null,
    subagentHitl: {},      // { [hitlKey]: SubagentHitlEntry }
    currentReplyId: null,
    sseController: null,   // AbortController，非响应式，见下方说明
  }),
  mutations: {
    RESET(state, { agentId, sessionId, memberId }) { /* 重置 messages/phase/error/hitl */ },
    SET_MESSAGES(state, msgs) { state.messages = msgs; },
    UPSERT_MESSAGE(state, msg) { /* 按 reply_id 替换或追加 */ },
    PATCH_REPLY(state, { replyId, patch }) { /* 整块替换单条 Msg，避免深字段细粒度改 */ },
    SET_PHASE(state, p) { state.phase = p; },
    SET_ERROR(state, e) { state.error = e; },
    UPSERT_HITL(state, entry) { /* subagent HITL */ },
    REMOVE_HITL(state, key) { /* ... */ },
  },
  actions: {
    async bindSession({ commit, dispatch, state }, { agentId, sessionId, memberId }) {
      // 切会话：中止旧 SSE → reset → 拉历史 → 开新 SSE
      await dispatch('closeStream');
      commit('RESET', { agentId, sessionId, memberId });
      if (!sessionId) return;
      commit('SET_LOADING', true);
      const msgs = await sessionApi.messages(sessionId);
      commit('SET_MESSAGES', msgs);
      commit('SET_LOADING', false);
      dispatch('openStream');
    },
    openStream({ commit, state, dispatch }) {
      const controller = new AbortController();
      commit('SET_SSE_CONTROLLER', controller);
      // 调用 sessionApi.streamEvents(sessionId, { signal })，async iterator 消费
      // 每帧 dispatch('processEvent', evt)
    },
    async closeStream({ state }) { state.sseController?.abort(); },
    processEvent({ commit, state }, evt) { /* 按 EventType 分发，见 §10.3 */ },
    async send({ dispatch, state }, payload) { /* chatApi.trigger + 置 streaming */ },
    async onUserConfirm({ dispatch }, payload) { /* POST /chat/ 携带确认事件 */ },
    async onSubagentConfirm({ dispatch }, payload) { /* ... */ },
    async interrupt({ dispatch, state }) { /* sessionApi.interrupt + 置 interrupting + 10s 兜底 */ },
  },
};
```

**响应式注意事项（Vue 2.6 限定）**：

- `sseController`（AbortController）、SSE reader 等非响应式「副作用句柄」**不要放进 state**，否则 Vue 2 的 `defineProperty` 会尝试代理它造成性能与正确性问题。改用模块级闭包变量持有：
  ```js
  let _sseController = null; // 模块作用域，不在 state 内
  ```
  actions 通过该闭包读写。state 只放需要驱动视图的数据。
- SSE 高频 `DATA_BLOCK_DELTA` 会持续改单条消息文本。按 §13 R1 对策：**节流合并**（如 50ms flush 一次）+ **整块替换单条 Msg**（`UPSERT_MESSAGE` 用新对象，不深改字段），避免每帧触发深层响应式追踪。
- 新增字段动态挂到 reactive 对象上不会自动响应（Vue 2 限定）。`Msg` 内若运行时新增 key，需用 `Vue.set` / `this.$set` 或预先声明字段。**优先构造完整骨架对象再赋值**。

## 5. Composables 层（L1/L2）

### 5.1 组合式 API 统一桥接

```js
// src/composables/vue.js
// 统一从 @vue/composition-api re-export，业务代码一律 import from '@/composables/vue'
// 将来切 Vue 3 时，把这里改成 from 'vue' 即可，业务代码不动。
export {
  ref, reactive, computed, watch, watchEffect,
  onMounted, onBeforeUnmount, onUnmounted,
  provide, inject, readonly, toRefs, toRef, unref,
} from '@vue/composition-api';
```

> 这是 Vue 2.6 方案的**关键迁移桥接点**，所有 composable 与组件都从这里导入，保证将来平移 Vue 3 只改一行。

### 5.2 CRUD composable 范式

26 个 hooks 中大量是「列表 + loading + actions」的同构模式。先写一个通用 `useResourceList`，再派生各业务 hook，减少重复：

```js
// src/composables/useResourceList.js
import { ref, shallowRef } from '@/composables/vue';

/**
 * @param {(params?: any) => Promise<{list: any[]}>} listFn
 * @param {object} [opts] { byId?: boolean }
 */
export function useResourceList(listFn, opts = {}) {
  const items = ref([]);
  const loading = ref(false);
  const error = ref(null);
  let reqId = 0;

  async function refetch(params) {
    const id = ++reqId;
    loading.value = true; error.value = null;
    try {
      const res = await listFn(params);
      if (id === reqId) items.value = res.list ?? res ?? [];
      return items.value;
    } catch (e) {
      if (id === reqId) error.value = e;
      return [];
    } finally {
      if (id === reqId) loading.value = false;
    }
  }

  return { items, loading, error, refetch };
}
```

业务 hook 在其上叠加 `create/update/remove`（调 api 后 `refetch`），对照 `useSessions.ts` 的模式原样翻译。需保留 React 原版里的「requestId 防竞态」「agentId 变化重拉」逻辑。

### 5.4 L2 provide/inject 壳范式

`useUploadCenter` / `useAudioCenter` 用 provide/inject 暴露，内部接 Vuex 或 manager 实例，调用方无感知实现：

```js
// src/composables/useAudioCenter.js
import { provide, inject, onBeforeUnmount } from '@/composables/vue';
import { StreamingAudioManager } from '@/utils/streamingAudio';

const KEY = Symbol('audioCenter');
export function provideAudioCenter() {
  const manager = new StreamingAudioManager();
  provide(KEY, manager);
  onBeforeUnmount(() => manager.disposeAll());
  return manager;
}
export function useAudioCenter() {
  const m = inject(KEY);
  if (!m) throw new Error('useAudioCenter must be used inside provider');
  return m;
}
```

`upload` 因已落 Vuex，`useUploadCenter` 只是对 `useStore` 的薄封装（提供与原 `useUploadContext` 同名的 `enqueue/cancel/dismiss/...` 接口），便于调用点最小改动。如未来希望降级回 L2，只需改这一个文件。

## 6. 数据层迁移（api/ 与 utils/ 去 TS 化）

### 6.1 复用原则

`api/`、`utils/` 是框架无关纯逻辑，**逻辑 100% 复用**，仅做「去 TS」处理：

- 删除所有 `interface/type` 声明、参数与返回值 `:Type` 注解、`<T>` 泛型、`as` 断言、`import type`。
- 关键 DTO（`Msg`、`AgentEvent`、`ContentBlock`、`ChatRequest`、`SessionView` 等）以 **JSDoc `@typedef`** 形式保留契约，便于 IDE 提示与后续维护。
- `client.ts` → `client.js`：fetch 封装、`X-User-ID` 头、422 解析、`silent` 模式、超时、`stream()` 全部原样保留。
- `utils/streamingAudio.ts` → `streamingAudio.js`：纯 TS + Web Audio API，无 React 依赖，**直接剥类型即用**，是本次迁移的「保命资产」。
- `utils/common.js`（formatNumber/clipboard 等）、`utils/platform.js` 原样复用。
- `lib/api-error.js`、`lib/utils.js`（`cn()`）原样复用。

### 6.2 `@agentscope-ai/agentscope` 处理

原项目用它取 `Msg`/`ContentBlock`/`AgentEvent` 类型 + `appendEvent`/`AssistantMsg`/`UserMsg` 运行时构造器 + `EventType` 枚举。

纯 JS 方案下：
- **运行时导出**（`appendEvent`、`AssistantMsg`、`UserMsg`、`EventType`）：若该包发布含 JS 产物，直接 `import` 使用；若无 JS 产物或不愿引入，则在 `src/api/messageFactory.js` 自持等价实现（对照旧版逻辑翻译）。
- **类型**：以 JSDoc `@typedef` 在 `src/api/types.js` 重述 `Msg`/`ContentBlock`/`AgentEvent` 结构（对照旧 `api/types.ts`），不依赖包的类型。
- **决策**：优先尝试直接 import 运行时导出；不可行则自持，**只依赖其数据结构定义，UI 全自持**（呼应 01 §R5）。

### 6.3 SSE 协议保留

`sessionApi.streamEvents(sid, { signal })` 仍是 **async generator**，内部 `fetch` + `response.body.getReader()` 按行解析 `data:` 帧、跳过 `:heartbeat`。这段逻辑框架无关，原样翻译到 `api/session.js`。`chat` 模块的 `openStream` action 消费该 generator。

### 10.2 `useMessages` composable（Vuex chat 模块封装）

```js
// src/composables/useMessages.js
import { computed } from '@/composables/vue';
import { useStore } from '@/composables/instance';

export function useMessages(agentId, sessionId, memberId) {
  const store = useStore();
  // 切会话时 dispatch bindSession

  return {
```

### 10.3 `processEvent` 事件分发

对照原 `useMessages` 的 `processEvent`，按 `EventType` 分发到 mutation：

### 10.4 流式 Markdown 渲染

无 streamdown，用 markdown-it 自封装增量渲染：

## 13. 风险与对策（按本方案更新）

| # | 风险 | 对策 |
|---|---|---|
| R1 | **Vue 2.6 响应式基于 defineProperty**：SSE 高频 delta + 长消息数组，更新粒度不当会卡顿；动态新增字段不响应 | 消息流增量**整块替换单条 Msg**（新对象，非深改字段）；delta 文本 **50ms 节流合并** flush；非响应式副作用句柄（AbortController/reader/manager）放模块闭包，**不进 state**；新字段用 `Vue.set` 或预声明骨架；长会话虚拟滚动 |
| R2 | **streamdown 无 Vue 版**：流式 Markdown 增量 + 代码高亮是体验关键 | markdown-it + highlight.js + katex + mermaid(异步) + DOMPurify；增量节流重渲染；mermaid 单独异步加载避免阻塞 |
| R3 | Vue 2.6 + composition-api 插件与 Vue 2.7/3 有差异，社区资料偏少 | 统一 `composables/vue.js` 桥接层隔离导入源；不使用 `<script setup>`；写法保持与 Vue 3 平移兼容（不用 `this`、不用选项式混用）；遇插件 API 差异查 `@vue/composition-api` 文档 |
| R4 | Vue 2.6 已 EOL，无安全补丁 | 团队既定基线，记录在案；保持 composables + Vuex modules 写法与 Vue 3 兼容，便于将来平移（桥接层是关键迁移点） |
| R5 | `@agentscope-ai/agentscope` 后续发版新增 UI 组件，Vue 侧无法跟进 | 只依赖其类型/数据结构定义（JSDoc 自持），UI 全自持；运行时导出优先尝试，不可用则自持等价实现 |
| R6 | 聊天链路回归成本高 | Phase 0 录制 SSE fixture，`chat` 模块用 fixture 回放做自动化冒烟；与旧版双开对照 |
| R7 | **去 TS 后失去类型保护**，DTO 字段拼错难发现 | 关键 DTO 用 JSDoc `@typedef` 保留契约；ESLint 加 `no-undef` 等基础规则；chat 模块 / api 层写最小单元用例覆盖字段映射 |
| R8 | **去 i18n 后文案散落各组件**，未来难统一 | 一次性从 `locales/zh.json` 抽取；高频复用文案（按钮「确定/取消」、状态词）集中到 `src/constants/text.js` 常量，组件引用常量而非字面量 |
| R9 | `@vue/composition-api` 不导出 `useRoute/useRouter/useStore` | 在 `composables/instance.js` 用 `getCurrentInstance()` 自封装，业务统一导入 |
| R10 | Vuex 模块化后命名空间调用繁琐 | 用 `mapState/mapActions` 带 namespace，或自写 `useMapper` 工具；chat/upload 等高频模块通过 composable（`useMessages`/`useUploadCenter`）封装，调用方不直接碰命名空间 |
