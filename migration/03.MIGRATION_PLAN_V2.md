## 4. Markdown 渲染管线（组件已就绪，重点是接入与适配）

### 4.1 管线全景

```
content prop
  → watch(immediate) ── 同帧合并（pendingUpdate 标志）
  → requestAnimationFrame 调度（每帧至多一次重算，内置渲染节流）
      ├─ remend(content)          # 自愈未闭合语法：流式中 "**粗体" → "**粗体**"，避免闪烁
      ├─ marked()                 # 自定义 renderer 输出 md-* class；gfm + breaks
      ├─ DOMPurify.sanitize()     # ADD_TAGS=CUSTOM_TAGS；ALLOW_DATA_ATTR=true
      └─ htmlparser2.parseDocument → AST
  → NodeRenderer 递归渲染（<component :is="tagName|组件">，v-bind="node.attribs"）
  → Vue patch diff：内容变化只更新变更的 vNode（增量 DOM 更新，非整段 innerHTML 替换）
```

相比 02 §10.4 的自研方案，省去的工作：解析器选型、增量渲染策略、节流、XSS 过滤、代码高亮（含行号 + 语言标签）、GFM 表格排版。这些均已实现。

### 4.2 组件契约与扩展点

| 契约 | 内容 | 用法 |
|---|---|---|
| props | `content: String` | 传入原始 markdown 文本（流式中传累积全文，非增量片段） |
| inject `CUSTOM_TAGS` | `string[]`（默认 `[]`） | 允许通过 DOMPurify 的自定义标签名白名单 |
| inject `CUSTOM_COMPONENTS` | `{ [tagName]: Component }`（默认 `{}`） | 把自定义标签映射为 Vue 组件；**必须传组件定义对象**（import 进来的 `.vue`），不能只传字符串名（NodeRenderer 未做全局注册，`:is` 收到字符串只会找原生标签/已注册组件，见 R15） |
| 性能特性 | rAF 同帧合并 + Vue diff | 上层只需保证 content 更新频率 ≤ 每帧一次即可，无需自己再写渲染节流 |
| 生命周期 | `beforeDestroy` 清理 rAF | Vue 2.6 命名，正确 |

**扩展机制设计**（数学公式 / mermaid，替代 02 中的 markdown-it-katex / mermaid 插件）：

1. 对 [MarkdownRenderer.vue](file:///Users/tang/workspace/projects/agentscope/examples/web_ui/frontend/src/components/common/MarkdownRenderer.vue) 的 `code` renderer 增加一个语言分支（约 5 行）：`lang === 'mermaid'` 时输出 `<md-mermaid code="${encodeURIComponent(text)}"></md-mermaid>` 而非 `<pre>`。
2. 聊天子树根部 provide：
   ```js
   provide('CUSTOM_TAGS', ['md-mermaid', 'md-katex']);
   provide('CUSTOM_COMPONENTS', { 'md-mermaid': MermaidBlock, 'md-katex': KatexBlock });
   ```
3. `MermaidBlock.vue` 懒加载 mermaid 库（`import('mermaid')`）渲染 SVG；`KatexBlock.vue` 懒加载 katex 渲染公式。两者独立异步，不阻塞消息主渲染（对应 01 R2 对策）。
4. 行内公式（`$...$`）如后续需要，再给 marked 加一段自定义 inline 规则，输出 `<md-katex>`——先不做，出现需求再加。

### 4.3 聊天流式接入（与 chat 模块的配合）

- SSE `DATA_BLOCK_DELTA` 的文本 delta 仍按 02 §13 R1 策略：**非响应式 buffer 累积 + 约 50ms flush 到响应式 content**。MarkdownRenderer 内部的 rAF 会再做一层同帧合并，双层节流下高频 delta 不会造成渲染风暴。
- `remend` 保证每个 flush 周期的中间态都是「合法渲染」的 markdown（未闭合语法自动补全），这正是流式体验的关键，**无需再自研增量渲染**。
- `ASMessageBubble.vue` 中每个 `TextBlock` 一个 `<MarkdownRenderer :content="block.text" />`；`ThinkingBlock` 用折叠容器内嵌 MarkdownRenderer。

### 4.4 必做适配任务清单

| # | 任务 | 原因 / 做法 |
|---|---|---|
| A1 | 建立 `src/styles/variables.less` | 组件样式引用了 `@text-color` 等未定义变量；且 Less 变量是**编译期**常量，运行时无法随 `.dark` 翻转。做法：Less 变量全部桥接到 index.css **已有的 CSS 自定义属性**（见下表），浅色/深色由现有 `.dark` 体系接管，**不改组件源码** |

| A3 | hljs 主题深色适配 | 组件内固定引入 `highlight.js/styles/vs.css`（浅色）。做法：保留该引入，深色下在 `.dark` 作用域内补一份覆盖样式（或在 `/dev/markdown` 验证后决定换 base16 主题 + class 切换） |
| A4 | `CUSTOM_TAGS`/`CUSTOM_COMPONENTS` 的 provide 约定文档化 | 统一在聊天子树根部注入，避免各组件零散 provide |
| A5 | marked 版本锁定 + 回归页 | renderer API 与 marked ≥5 的 token 模型耦合，升级需回归（见 R13） |
| A6 | （可选）`defineComponent` 导入源统一 | 两个组件直接 `from '@/composables/vue'`；02 的桥接层 `composables/vue.js` 面向 composables。组件内导入源不强求改写，团队统一即可，**不阻塞** |

**A1 的变量桥接表**（写入 `variables.less`）：

```less
// —— 编译期桥接：SFC 中的 Less 变量 → 运行时 CSS 自定义属性 ——
@text-color:       var(--foreground);          // index.css :root/.dark 已定义
@text-secondary:   var(--muted-foreground);
@border-color:     var(--border);
@primary-color:    var(--primary);
@code-bg:          var(--muted);
@surface-muted:    var(--muted);
@spacing-xs: 4px;  @spacing-sm: 8px;  @spacing-md: 16px;  @spacing-lg: 24px;
@border-radius-sm: 4px;  @border-radius-md: 8px;
```

> 好处：md 组件、Element 覆盖层（§5.4）、业务 Tailwind 组件三者共用同一套 `.dark` 变量体系，深色模式只维护 index.css 一处。

### 5.3 自实现组件实现要点

- 全部放在 `src/components/ui/`（.vue，与旧目录同名对应，调用方路径好对照）。
- 样式：**直接复用原 tsx 里的 Tailwind class**（shadcn 组件本质是 class 组合 + cva 变体），cva 变体思路用 computed 拼接 `cn()`。
- 事件与 v-model：`props.value` + `$emit('input')` 对齐 Vue 2 的 v-model 约定；`props.modelValue` 不用（那是 v-model:argument / Vue 3 风格）。
- 自实现组件不多做抽象：与原 tsx 一一对应，视觉 100% 还原。

### 5.4 主题与深色模式（双轨样式边界）

三条边界，避免样式互相污染：

| 层 | 体系 | 说明 |
|---|---|---|
| 业务组件（views/chat/panel/dialog...） | **Tailwind v4** | 原 class 原样搬运，index.css 不动 |
